# 生圖：跨裝置適配與可行性報告

> 2026-09-29。結論：**可行**。遊戲引擎已經支援圖片，並在 7 種裝置尺寸上以測試圖實測過。
> **2026-09-30 定案**：方式 C（作者電腦上的 Claude Code 桌面版）、水墨淡彩、頭像用原生透明背景、第一批 47 張（背景 30＋頭像 17）。操作方式見 `千秋硯/tools/生圖/README.md`。

---

## 1. 引擎已經做好的部分

| 功能 | 劇本寫法 | 畫面 |
|---|---|---|
| 場景背景圖 | `@背景 新港社` | 取代頂部的紋樣橫幅；點一下橫幅可以全螢幕看完整的圖 |
| 劇情插圖 | `@插圖 祖母過河 說明文字` | 插在文字流裡，全寬顯示；點一下可以全螢幕檢視 |
| 角色頭像 | 自動（依對白的角色名稱） | 對白名字旁的小圓形頭像 |
| 不同年紀的頭像 | `@立繪 蒂娃 蒂娃_38` | 之後蒂娃的對白改用「蒂娃_38」這張 |
| 敵人圖 | 自動（依敵人名稱） | 戰鬥時敵人卡片右上角 |

- 圖片清單放在 `千秋硯/img/manifest.json`。**沒有列在清單裡的圖不會被載入，畫面自動退回原本的紋樣**，所以可以一邊生圖、一邊陸續上架，不會出現破圖。
- 圖片載入失敗（例如離線且沒看過）時，也會自動隱藏，不影響遊戲。

## 2. 實測結果（7 種裝置）

測試方式：用程式產生「雜訊很多、比真實畫作更難壓縮」的測試圖（最壞情況），在無頭瀏覽器中模擬各裝置。

| 裝置 | 橫幅實際大小（比例） | 下載的背景圖 | 插圖顯示大小 | 問題 |
|---|---|---|---|---|
| iPhone SE 375×667 | 375×128（2.9:1） | 800 寬 | 351×234 | 無 |
| iPhone 15 393×852 | 393×134（2.9:1） | 1600 寬（3 倍螢幕） | 369×246 | 無 |
| Android 360×780 | 360×122（2.9:1） | 1600 寬（3 倍螢幕） | 336×224 | 無 |
| iPad 直向 820×1180 | 720×260（2.8:1） | 1600 寬 | 696×464 | 無 |
| iPad 橫向 1180×820 | 720×246（2.9:1） | 1600 寬 | 696×464 | 無 |
| 手機橫向 852×393 | 720×86（8.3:1） | 1600 寬 | 696×236 | 橫幅很窄，只看得到中間一條（見下） |
| 電腦 1440×900 | 720×260（2.8:1） | 800 寬 | 696×464 | 無 |

- 所有裝置：無程式錯誤、無橫向捲動、頭像與敵人圖正常顯示。
- 瀏覽器會依螢幕自動挑選 800 或 1600 寬的版本，普通螢幕只下載小圖。
- **手機橫向**時橫幅只剩 86px 高，只露出畫面中間約兩成。玩家點橫幅仍可看全圖；因此構圖規定「主體放在中間」（見第 3 節）。

## 3. 生圖規格

| 類別 | 生成尺寸（建議） | 上架檔案 | 構圖規定 |
|---|---|---|---|
| 場景背景 `bg` | 16:9（Qwen-Image 常用 1664×928） | `名稱-1600.webp`、`名稱-800.webp` | **主體放在垂直方向的中間 40%**；左下角會疊地名文字，避免放重要物件 |
| 劇情插圖 `cg` | 3:2（常用 1584×1056） | `名稱-1600.webp`、`名稱-800.webp` | 完整顯示，不裁切 |
| 角色頭像 `char` | 1:1（常用 1328×1328） | `名稱.webp`（512×512） | 臉放在畫面中央偏上，背景單純 |
| 敵人 `enemy` | 1:1 | `名稱.webp`（512×512） | 主體置中，背景單純 |

- 格式一律 WebP（品質約 80）。iOS 14 以上、所有現代 Android 與電腦瀏覽器都支援。
- 批次腳本會自動把生成的大圖縮成上架尺寸、轉成 WebP、並更新 `manifest.json`。

## 4. 檔案大小與流量

測試圖（最壞情況）的實際大小：

| 類別 | 1600 寬 | 800 寬 |
|---|---|---|
| 背景 | 約 105 KB | 約 40 KB |
| 插圖 | 約 150 KB | 約 63 KB |
| 頭像、敵人 | 約 26～29 KB（512） | — |

以卷一約 80 張估算：

| 項目 | 估計 |
|---|---|
| 高解析度手機玩完整卷一的總下載量 | 約 5～6 MB（分散在 5～7 小時的遊玩中） |
| 一般螢幕 | 約 2～3 MB |
| 儲存庫增加的容量（兩種尺寸都放） | 約 7～8 MB／卷；全部 12 卷約 90 MB |
| GitHub Pages 限制 | 網站 1 GB、單檔 100 MB——綽綽有餘 |

真實的水墨或插畫通常比測試圖更好壓縮，實際會更小。

## 5. 離線

- 圖片**不會**在安裝時全部下載（避免第一次開啟太慢）。
- 看過的圖會被離線快取保存，之後沒網路也能看到。
- 沒看過又沒網路時，畫面退回紋樣，遊戲照常進行。

## 6. 串接方式與待決事項

雲端的執行環境**連不到玩家或作者電腦上的本機 API**（例如 `localhost:8188`），因此「由 Claude 直接呼叫本機工作流」需要以下其中一種方式：

| 方式 | 做法 | 優點 | 缺點 |
|---|---|---|---|
| **A. 本機腳本（推薦）** | Claude 寫好「生圖清單＋批次腳本」，作者在電腦上執行一行指令；腳本呼叫本機工作流、轉檔、更新清單 | 安全，電腦不對外開放 | 圖需要由作者上傳到 GitHub（網頁拖拉資料夾即可） |
| B. 對外通道 | 以 Cloudflare Tunnel 等工具把 API 開放給雲端 | 全自動 | 需要設定通道與密碼，有安全風險 |
| C. 本機 Claude Code | 在自己電腦上用 Claude Code 桌面版開啟此專案 | 自動化程度最高 | 需要安裝設定 |

待決事項：

1. 串接方式（A／B／C）
2. 美術風格（水墨淡彩／古風插畫／寫實歷史畫／木刻版畫）
3. 第一批範圍（背景＋頭像約 40 張，或全部約 80 張）
4. 工作流 JSON（ComfyUI「匯出（API 格式）」；文生圖與圖生圖各一份）
5. 模型授權是否允許用於公開網站

## 7. 需要人工把關的內容

- 西拉雅族服飾容易被 AI 畫成刻板的「泛部落風」，需要參照資料並由作者審圖；祭儀場面一律不畫。
- 真實歷史人物（鄭成功、揆一等）原則上只畫遠景或背影。例外：古代人物形象主要來自雕像或文獻、又需要在對話中出現的，可以畫正面頭像（例如卷四的蘇格拉底、柏拉圖、克里提亞斯，2026-10 作者決定），描述時參照該時代的雕像與服裝。
- 採用 AI 圖等於修改企劃書第 12 項決策（原為「公有領域名畫＋程式紋樣」），確認後會記入決策紀錄。
